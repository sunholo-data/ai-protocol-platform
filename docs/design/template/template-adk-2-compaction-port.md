## Problem

Three files import private helpers from `google.adk.apps.compaction`:

| File | Helper | 1.39.1 | 2.12.0 |
|---|---|---|---|
| `backend/adk/compaction_second_pass.py:136` | `_pending_function_call_ids` | ✅ | ❌ **removed** |
| `backend/adk/compaction_second_pass.py:136` | `_truncate_events_before_pending_function_call` | ✅ | ❌ **removed** |
| `backend/adk/compaction_second_pass.py:136,214` | `_valid_compactions`, `_latest_compaction_event` | ✅ | ✅ |
| `backend/admin/compaction_second_pass_routes.py:62` | `_latest_compaction_event` | ✅ | ✅ |
| `backend/admin/compaction_replay_routes.py:84` | `_events_to_compact_for_token_threshold` | ✅ | ✅ |

The table was verified by grepping the unpacked 1.39.1 and 2.12.0 wheels on 2026-10-16. On 2.12 the import fails at call time, inside a function body. So an un-exercised path would only break on the first second-pass run, which is **worse** than an import-time failure.

Compaction itself changed repeatedly between 1.32 and 2.12 (changelog lines 158, 159, 164, 168, 285, 424, 460, 540, 838, 1029, 1108, 1276, 1426–1427, 1762, 1841). Notably, thoughts and tool calls are now included in summaries (1841), and 2.6 adds optional sliding-window fields (1276).

## Design

1. **Own the pending-call logic in-tree.** Create `backend/adk/compaction_compat.py` with `pending_function_call_ids(events)` and `truncate_events_before_pending_function_call(events, ids)`, copied from the 1.39.1 source with attribution (Apache-2.0). These are small pure functions. Owning them is better than tracking ADK's replacement, whose semantics may have moved with the 2.x compaction rework.
2. **Route every private import through `compaction_compat`.** That makes it the one file to touch on future bumps. Helpers that still exist (`_valid_compactions`, `_latest_compaction_event`, `_events_to_compact_for_token_threshold`) get thin re-exports there with a version comment.
3. **Add a parity test** (`adk_contract`): for a fixture event list containing a pending function call, our ported functions give the same result as the 1.39.1 originals. Record the expected output as a golden file, so the test keeps working once 1.39.1 is gone.
4. **Add a behaviour test on 2.12:** live compaction followed by a second pass. The second pass still subsumes every prior compaction, still fails safe on a pending call inside the span, and the live retention floor is still respected. Extend the existing `test_compaction_second_pass.py`.
5. **Re-check the summarizer:** `adk/compaction_summarizer.py` subclasses `LlmEventSummarizer`. With 1841, the summarizer input now includes thoughts and tool calls. Confirm our prompt still fits the token budget, and that confidential tool results don't get echoed into a summary that has wider visibility than the session itself (CLAUDE.md security rule).

## Implementation (2026-10-17)

No dependency, `pyproject.toml` or `uv.lock` change. Everything below runs on the current 1.31.1 pin.

**1–2. `backend/adk/compaction_compat.py`** is now the only module in `adk/` and `admin/` that imports `google.adk.apps.compaction`.

- **Owned:** `pending_function_call_ids` and `truncate_events_before_pending_function_call` are ported from 1.39.1 with the Apache-2.0 notice. The 1.31.1 originals are byte-identical. Only the names and formatting changed.
- **Re-exported:** `valid_compactions`, `latest_compaction_event` and `events_to_compact_for_token_threshold` are thin wrappers with a *deferred* import. That keeps the cold-import behaviour the callers already had.
- **Callers switched:** `adk/compaction_second_pass.py`, `admin/compaction_second_pass_routes.py` and `admin/compaction_replay_routes.py`.

**3. `backend/tests/unit/test_compaction_compat_parity.py`** (`adk_contract`) and its golden file `backend/tests/unit/golden/compaction_compat_parity.json`:

- The golden was generated by the real 1.39.1 helpers. It records `generated_with.google_adk = "1.39.1"`, and a test asserts that value.
- The fixture covers answered, late-answered, id-less, never-answered and orphan-response calls, plus a mid-session slice shaped like a second-pass span.
- Where the originals still import (1.31.1, 1.39.1), they are also checked against the golden.
- The test also checks two things on every venv: (a) each re-export resolves and runs, and (b) a source scan finds no `google.adk.apps.compaction` import in `adk/` or `admin/` outside the shim.
- To regenerate the golden, run this on the 1.39.1 venv only: `COMPACTION_GOLDEN_REGENERATE=1 .venv-adk1391/bin/python -m pytest tests/unit/test_compaction_compat_parity.py`.

**4. `TestLiveCompactionThenSecondPass`** in `test_compaction_second_pass.py` (`adk_contract`). The *installed* ADK's `_run_compaction_for_token_threshold_config` writes the live compactions, and our second pass then runs on top of them.

- **Subsume and retention:** two live compactions, `[1,4]` then a seeded `[1,6]`. The second pass claims `[1,6]` and summarises exactly the six raw events in it. `_latest_compaction_event` picks our event. The real contents pipeline serves only our summary plus the `event_retention_size` raw turns, untouched.
- **Fail-safe:** this is a real 2.x behaviour change. 1.x live compaction stops *before* an unanswered call, at `[1,1]`. 2.x's `_longest_self_contained_prefix` compacts *past* a call it can prove dead (older invocation, no response anywhere), at `[1,5]`. On 2.x a pending call can therefore now sit *inside* a live span, and the second pass declines. The test asserts the branch for each major version.

## Findings

### F1. Summarizer re-check (Design item 5). No code change.

- **1841 does not reach us.** `FidelityEventSummarizer` overrides `_format_events_for_prompt` *completely*. So the 2.12 base-class change (thoughts and tool calls in the input, 2000-char tool cap) does not alter what our summarizer sees. We still skip thoughts, which is deliberate (see the comment in the override), and still cap each tool payload at 4000 chars, flagged when truncated. The prompt-size profile is unchanged from 1.31.1. There is no total input cap, which was also true before the bump.
- **Credential events: confidentiality gap, pre-existing, not introduced by the bump.** The 2.12 base summarizer skips credential-request events (`_is_auth_event`), "because their payload is the end user's credential". Our override has never done this, on any version. An `adk_request_credential` call or response in the compacted span would be rendered into the summarizer prompt (up to 4000 chars), could be echoed into a summary, and summary text is returned by the admin replay and recompact routes. This is **not verified** against a real session: I did not check whether ADK auth-flow events occur in our sessions, and I wrote no test. Because of that, and the scope rule for this item, the summarizer code was left unchanged. **Recommended follow-up (small):** add a test that feeds an auth event through `_format_events_for_prompt`, then skip those events the way the 2.12 base does. Do this before or with 03b.
- **Visibility otherwise unchanged.** `HISTORY_COMPACTED` / `COMPACTION_STARTED` stay metadata-only. Summary text leaves the session only through the two `PlatformScope` admin routes, as before.
- **2.12 interaction to watch in 03b.** 2.x adds `_is_range_worth_compacting`: a live compaction is skipped unless the range can save more than the *previous summary's* size. Our prompt asks for long summaries ("prefer a long summary that keeps the facts"). On 2.x, a long summary therefore raises the bar for the next live compaction. Expect fewer, later compactions, and measure this in 03b's eval deltas.

### F2. Second pass vs 2.x dead-call compaction

Covered by the test above. For sessions with an orphaned call inside the live span, the second pass now always declines on 2.x. That is safe, but it means no improvement for those sessions. If it shows up in `nothing_to_improve` counts after 03b, the second pass could adopt a "provably dead" rule of its own. That decision belongs with this file, not with ADK.

### F3. For 03a: `a2ui` breaks on 1.39.1 already

On the 1.39.1 **and** 2.12 venvs, every test whose imports reach `adk.agent` / `adk.a2ui` errors at collection with `NameError: name 'models' is not defined` inside the installed `a2ui` package. That is 16 collection errors under `-m adk_contract tests/unit`, plus the remaining compaction-file failures there. This is a dependency-resolution break that surfaces at 1.39.1, so 03a owns it, not 04. The parity test imports only the compaction modules so that it collects everywhere.
