# v6.7.0 Build Sequence

**Gate:** v6.6.0 fork-convergence substantially landed (model tiers ✅, Skill Studio ✅, per-skill persona ✅). v6.6.0 workstream D shipped named tiers with the *intent* of "deep work via sub-skill delegation, not router swap" — but delegation itself was never wired (every skill ships `subSkills=[]`, and the sub-skill access path was inert).

**Status as of 2026-07-08:** One doc planned — `skill-delegation.md` (7.1, sprint key SKILL-DELEGATION). Turns the anticipated-but-unbuilt delegation mechanism into a configurable, access-aware, UI-signaled feature.

**Theme:** Make a skill able to hand a turn to an allow-listed specialist skill when the parent LLM judges it would do better — enforced against the requesting user's access level *by construction* (closing a live escalation gap), signaled live over AG-UI (transient "Handing off…" label + persistent transcript marker), authorable in Skill Studio.

## What ships in v6.7.0

**From 7.1 (skill-delegation):**
- **`DelegationConfig` on `SkillMetadata`** (`enabled`/`mode`/`allow`/`max_depth`); `sub_skills` kept as read-compat alias → `delegation.allow`. Default off, no backfill.
- **Access-gap fix (security)** — `access_context` threaded `skill_processor` → `create_agent_with_thinking` → `create_agent`; delegate targets filtered by `AccessContext.can_access_skill` (deny-by-default). Closes a live privilege-escalation side channel; safe to keep even if delegation is disabled.
- **Auto + suggest modes** — `auto` via ADK `transfer_to_agent`; `suggest` via a `propose_delegation` tool + confirm-then-re-issue path.
- **AG-UI signaling** — `STAGE_PROGRESS` "Handing off…" (transient) + new `AGENT_DELEGATION` marker (persistent), over the existing `CustomEvent` drain path (no new wire format).
- **Frontend** — `useSkillAgent` `AGENT_DELEGATION` branch → persistent marker; new `DelegationMarker.tsx` (<2KB).
- **Skill Studio** — `delegation` block editor with an access-scoped allow-picker (lists only skills the author can access).
- **CLI** — `aiplatform skill probe` prints delegation events for headless verification.
- **Seeded example** — `general-assistant` gains an opt-in `delegation.allow` (e.g. `one-ppa-expert`) in dev.

**From 7.2 (ppa-compare-launcher):**
- **M1 (shipped 2026-07-09)** — slim `PpaDifferences` response schema (fixes Vertex `400 too-many-states-for-serving`); `PpaWorkspacePanel` mounts the previously-orphaned `KeyDifferencesPanel` + `ClauseExtractionCard` on the Workspace tab, derived from the tool-call stream (progressive fill); transparent `other_clauses` cap (no silent truncation); client-side severity/clause filters; PPA tools routed through model tiers (`gemini_api_name_for`, extraction=lite / comparison=pro).
- **M2 (planned)** — A2UI workbench "Compare contracts" launcher (one-click, no typed intent) over the existing `surface-action-run` loop; inline-chat A2UI config form (clause subset / severity floor / depth); per-skill `allow_action_triggered_runs` opt-in; `aiplatform skill compare` CLI verb.

**From 7.3 (tool-results-as-a2ui) ✅ shipped 2026-07-09:**
- **Result→A2UI mapping registry** (`adk/a2ui_result_render.py`) + out-of-model `A2UI_SURFACE` CUSTOM-event emission (`make_a2ui_result_emitter` → `LatencyTracker.emit_a2ui_surface` → `SurfaceRegistry`); registry-driven offload exemption (retired hardcoded `_RENDER_PAYLOAD_TOOLS`).
- **PPA compare/extract as A2UI** — tabbed compare surface (nested severity filter), per-document extract tabs, filename resolution, compact clause rows, app-accent theming; **deleted the 4 bespoke panels + hook** (~1,600 LOC). Interaction: diff "Explain this difference" → `chat:send` → chat turn.
- **CLI** — `aiplatform a2ui render` + `make a2ui-render` headless preview.

**From 7.5 (workbench-artifacts-model, ✅ shipped 2026-07-09):**
- Per-result artifact surfaces + dynamic workbench tabs; Workspace tab → landing index/timeline (≥2 artifacts); resume rehydration (emitter stashes rendered surfaces to session state → session-history GET replays them on refresh); Model-B skills (`one-doc-compare`, `one-ppa-expert`) no longer granted the direct A2UI toolset (`a2ui.enabled: false`); PPA extract + compare result caching (skip redundant LLM calls). Follow-up tracked: interaction/rendering-model redesign (design doc Open Question).

**From 7.7 (model-reliability):**
- **Phase 0 transport/stall hotfix (long-stream-class, independently shippable)** — proxy SSE path switched from undici `fetch()` (hardcoded 300s body timeout) to `node:http` streaming; `--timeout=3600` on the Cloud Run deploy; SSE heartbeats on the chat stream; mid-stream inactivity watchdog (existing 30s watchdog only covers pre-RUN_STARTED); `scripts/smoke-long-stream.sh` regression guard.
- **Typed model errors for all providers** — new `adk/model_errors.py` classifier (Gemini `ClientError`/`ServerError`, LiteLLM exception families incl. Anthropic 429/529); `skill_processor` emits `MODEL_UNAVAILABLE` / `MODEL_RATE_LIMITED` / `MODEL_AUTH_FAILED` / `MODEL_REQUEST_INVALID` RUN_ERRORs (today LiteLLM errors die silently).
- **Retry + fallback chains** — `ResilientLlm(BaseLlm)` wrapper (backoff w/ full jitter, 2 retries/model, visible-output gate, per-provider cooldown); declarative `fallbacks:` per model in `models.yaml` + optional `SkillMetadata.fallback` override; empty chain = passthrough (zero change for unconfigured skills).
- **User-visible degradation** — transient `MODEL_RETRY` + persistent `MODEL_FALLBACK` CUSTOM events over the existing drain path; `FallbackNotice.tsx` transcript chip ("Answered by backup model X — Y was unavailable"); `classifyRunError` copy for new codes.
- **Thinking visibility** — the REASONING→ThinkingPanel pipeline is already wired end-to-end (ag_ui_adk translator + `onReasoningMessageContentEvent`) but dark: Gemini planner lacks `include_thoughts=True`, Claude gets no `thinking` kwarg (= thinking OFF on Opus 4.7+). Phase 3 turns thought emission on at the model layer (`display: "summarized"` mandatory on Claude 4.7+ — default `"omitted"` streams empty text, so the v5 thinking-tokens-as-keep-alive trick silently dies there; heartbeats are the transport guarantee instead). Throttled "Thinking…" `STAGE_PROGRESS` fallback for silent phases.
- **Deployment residency policy (by construction)** — `MODEL_RESIDENCY_POLICY` env (`eu-strict` | `unrestricted`) enforced at the `resolve_model_chain` choke point: under `eu-strict` non-EU entries cannot enter a chain (fallbacks dropped loudly, pinned non-EU primaries fail at load — never a silent swap). Residency-aware `tier_defaults` variants mean an `eu-strict` deployment resolves every tier to an EU model + EU chain with zero skill changes. Aitana prod = `eu-strict` (hard requirement — EU-resident), dev + test = `unrestricted` (both run the faster global-endpoint 3.x line — updated v6.8.0; canonical per-env record: `docs/ops/env-config-parity.md`); template ships `default_policy: eu-strict`, forks opt out in one reviewed line.
- **Fallback provider landscape (EU-first)** — `ResilientLlm` is our router; external gateways only earn a place when they grant an unreachable capability. Rung order exhausts the trust boundary first: Tier 1a **same model, other EU region** (`RegionalGemini` location override; Vertex quota is per project+region so 429s genuinely clear cross-region; `make verify-regions` guards per-region model drift) → Tier 1b sibling model, same provider → Tier 2 direct EU endpoints (Mistral La Plateforme; Claude on Bedrock eu-central-1 — would be the first EU-resident Claude, candidate to retire the US-direct smart-tier exception, verify with AWS) → Tier 3 EU routers (Requesty EU Frankfurt/OpenAI-compatible ≈ free integration; EdenAI EU `api.eu.edenai.run` own v3 API ≈ ~1d adapter; EUrouter; vendor claims → DPA items) → Tier 4 OpenRouter/Anthropic-US (dev/demo + non-EU forks only). **Deferred spike (lower roadmap):** probe EU providers' actual catalogs/TTFT/ZDR + PPA evalset per candidate rung before any tier-2/3 entry ships; config schema already accommodates results.
- **Egress guard** — cross-provider fallback that widens egress (gemini/EU → claude/US) requires per-skill `fallback.allow_cross_provider: true`.
- **Tooling/observability** — `FAULT_INJECT_MODEL` fault injection (dev-only) + `make probe-fallback`; `aiplatform skill probe` prints retry/fallback events; OTel counters by provider/code.
